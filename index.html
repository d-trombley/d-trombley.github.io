Invoice agent

Open the live demo. Made-up vendors and invoices, no sign-in.

Checks every emailed invoice against its PO and receipt. A person only sees the ones that are wrong.

  • Results: in a full run with Claude on a 40-invoice test set, every field was read correctly, all 9 invoices with planted problems were caught, and there were 0 false flags. About 2 cents and 4 seconds per invoice. 100+ automated tests.
  • How it works: Claude reads each PDF and returns the fields with a confidence score. Code does the math in whole cents, applies the 2% price tolerance, catches duplicates and checks every vendor and PO against the ledger.
  • Exceptions: unsure fields and every flag (price over PO, short shipment, duplicate, changed bank details) go to a queue. A flagged invoice needs a written reason to approve.
  • Controls: Claude can't approve anything. Every step is logged with its inputs, the model output and its cost.
  • Next: sign-in with roles, a second approver above a set amount, and a weekly accuracy check.

Monthly client reports

In production for about 6 months at StoreAssure Digital. It runs on client data, so there's no public demo.

Three agents build each client's monthly marketing report and check every figure against the source data. I sign off before it goes out.

  • Results: each report went from about 3 hours to about 10 minutes.
  • How it works: a data agent pulls the month's numbers, a design agent fills the template, and a review agent checks every printed figure against the source data on its own.
  • Setup: each client is set up once with instructions and data connections. No model retraining.
  • Controls: the review agent's check against source data, then my sign-off.
  • Next: time one report by hand to record a baseline, and track the review agent's catch rate each month.

Cash receipts matching

Live demo coming soon.

Applies bank deposits to open invoices and builds the journal entry. A clerk works the exceptions and a controller approves the batch.

  • Results: from the rules engine, 72.7% applied automatically with 0 wrong, 99.9% right after review (801 of 802), and the journal entry ties to the answer key to the cent.
  • How it works: rules apply the payments they can prove. Claude suggests a match for the rest, with its reasoning and a confidence level. If code rejects an answer, the payment goes to exceptions with the reason.
  • Controls: the clerk accepts or edits each suggestion. Claude can't apply, approve or post anything. Clean matches still go into the batch the controller approves.
  • Testing: a score page grades each measure against the answer key and lists every miss. 121 automated tests.
  • Test data: 129 bank lines and 1,127 open invoices from one month of a published accounting dataset, with fees, short pays, payer name variants and missing remittances added.
